# Phase 1: Bucket Deadlines

## Context

Phase 1 is the foundation for all of v0.10.0. It adds deadline and saving rule fields to every bucket, implements pace tracking with historical analysis, introduces the Sequential Focus system (max 2 focus buckets), and migrates existing users. After Phase 1, users see exactly what to save today, which bucket to focus on, and whether they're on track.

**Prerequisites**: None (first phase).
**Depends on**: Nothing.
**Blocks**: Phase 2 (templates use deadline/rule fields), Phase 3 (dashboard shows pace data), Phase 4 (notifications use pace status).

**Key decisions** (see master plan for full list):
- Every bucket must have a deadline (D7)
- 6 rule types including `flexible` (D14, D15)
- Historical pace, 4 warning levels (D25, D26)
- Sequential Focus with max 2 (D19-D24)
- Saving Plan → auto-sum from bucket rules (D29)
- Client-side pure functions for pace (D48)
- Bangkok timezone for all date math (D49)

**Files that already exist and must be understood before editing**:
- `src/lib/bucketIntent.ts` — current focus/next/done logic
- `src/lib/savingPlan.ts` — Bangkok date math helpers (reuse)
- `src/types/index.ts` — Bucket, SavingPlan, SavingPlanRevision interfaces
- `src/hooks/useBuckets.ts` — bucket CRUD
- `src/hooks/useSavingPlan.ts` — plan fetch/archive
- `src/components/BucketRow/BucketRow.tsx` — current bucket card
- `src/components/BucketSheet/BucketSheet.tsx` — bucket create/edit form
- `src/components/BucketGrid/BucketGrid.tsx` — bucket list + drag
- `src/components/SavingPlanCard/SavingPlanCard.tsx` — plan display on dashboard

## Slice 1.1: Schema Migration

**Status**: [ ] pending

### What
Add deadline, saving rule, and related fields to the `buckets` table. Create `bucket_deadline_revisions` audit table. Add `completed_at` to track bucket completion timestamp.

### Files to touch
- `supabase/migrations/0071_bucket_deadlines_and_rules.sql` (new)

### Implementation detail

```sql
-- New columns on buckets
ALTER TABLE buckets
  ADD COLUMN deadline date,
  ADD COLUMN saving_rule_type text,
  ADD COLUMN saving_rule_amount numeric,
  ADD COLUMN saving_rule_start_amount numeric,
  ADD COLUMN saving_rule_increment numeric,
  ADD COLUMN saving_rule_cap numeric,
  ADD COLUMN saving_rule_day_count integer,
  ADD COLUMN reminder_day integer,
  ADD COLUMN payment_type text DEFAULT 'flexible',
  ADD COLUMN completed_at timestamptz;

-- Constraints
ALTER TABLE buckets
  ADD CONSTRAINT chk_saving_rule_type CHECK (
    saving_rule_type IS NULL OR saving_rule_type IN (
      'fixed_daily','fixed_weekly','fixed_monthly',
      'increasing_daily','increasing_daily_capped','flexible'
    )
  ),
  ADD CONSTRAINT chk_payment_type CHECK (
    payment_type IN ('advance_booking','pre_trip','on_trip','flexible')
  ),
  ADD CONSTRAINT chk_reminder_day CHECK (
    reminder_day IS NULL OR (reminder_day >= 1 AND reminder_day <= 28)
  );

-- Audit table for deadline changes
CREATE TABLE bucket_deadline_revisions (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  bucket_id uuid NOT NULL REFERENCES buckets(id),
  previous_deadline date,
  new_deadline date NOT NULL,
  changed_by uuid NOT NULL REFERENCES auth.users(id),
  changed_at timestamptz NOT NULL DEFAULT now()
);

-- RLS: same as buckets (room-member read, owner write)
ALTER TABLE bucket_deadline_revisions ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Room members can view deadline revisions"
  ON bucket_deadline_revisions FOR SELECT
  USING (
    EXISTS (
      SELECT 1 FROM buckets b
      JOIN room_members rm ON rm.room_id = b.room_id
      WHERE b.id = bucket_deadline_revisions.bucket_id
        AND rm.user_id = auth.uid()
    )
  );

CREATE POLICY "Bucket owner can insert deadline revisions"
  ON bucket_deadline_revisions FOR INSERT
  WITH CHECK (changed_by = auth.uid());
```

### Notes
- `deadline` is nullable initially to support migration window (existing buckets have no deadline yet). After migration wizard completes for a user, their buckets will all have deadlines.
- Do NOT add NOT NULL constraint on deadline yet — that comes after migration is complete (or enforced at app level).
- `saving_rule_type` is nullable: null = no rule set yet (pre-migration state).
- Reuse existing bucket RLS patterns. Do not create recursive policies.

### Acceptance criteria
- [ ] Migration runs clean on fresh DB
- [ ] Migration runs clean on existing DB with populated buckets
- [ ] Existing bucket data unchanged (all new columns null/default)
- [ ] `bucket_deadline_revisions` has correct RLS
- [ ] `npm run build` passes

### Implementation detail

**Types to add** (`src/types/index.ts`):
```typescript
type SavingRuleType =
  | 'fixed_daily'
  | 'fixed_weekly'
  | 'fixed_monthly'
  | 'increasing_daily'
  | 'increasing_daily_capped'
  | 'flexible';

type PaymentType = 'advance_booking' | 'pre_trip' | 'on_trip' | 'flexible';

type PaceStatus = 'ahead' | 'on_track' | 'behind' | 'critical';

type BucketFocusState = 'focus' | 'next' | 'queued' | 'done' | 'overdue';

interface BucketPace {
  status: PaceStatus;
  percentSaved: number;
  percentExpected: number;
  remainingAmount: number;
  remainingDays: number;
  requiredPerDay: number | null;    // null for flexible
  requiredPerPeriod: number | null; // null for flexible
  projectedCompletionDate: string | null;
}

interface DailySummaryItem {
  bucketId: string;
  bucketName: string;
  category: BucketCategory;
  ruleType: SavingRuleType;
  amountDue: number | null;     // null for flexible/monthly-not-yet-due
  periodLabel: string;          // "today", "this week", "this month", "flexible"
  periodDeadline: string | null; // when this period ends
  isFocus: boolean;
}
```

**Pace calculation** (`src/lib/paceCalculation.ts`):
- `calcBucketPace(bucket, deposits, today)` → `BucketPace`
  - Historical pace: weighted average of recent deposit velocity
  - Linear fallback when < 3 deposits
  - 4-level status thresholds: ahead ≥ +10%, on_track ±10%, behind ≥ -1%, critical < 30% time + < 70% saved
  - All date math uses Bangkok timezone (reuse helpers from `src/lib/savingPlan.ts`)

**Daily summary** (`src/lib/bucketDailySummary.ts`):
- `calcDailySummary(buckets, deposits, today)` → `DailySummaryItem[]`
  - fixed_daily → amount due today
  - fixed_weekly → amount due this week (null if already met)
  - fixed_monthly → amount due this month (null if already met); show days until reminder_day
  - increasing_daily → today's specific amount
  - flexible → null amount, show % progress only
  - Only focus buckets included

**Sequential Focus** (`src/lib/bucketFocus.ts`):
- `calcBucketFocusStates(buckets, deposits, today)` → `Map<string, BucketFocusState>`
  - Sort active buckets by deadline ascending
  - First incomplete bucket by deadline = `focus`
  - If 2 buckets have overlapping urgent deadlines (both within 30 days and both behind) = both `focus`
  - Max 2 focus at once; rest = `queued`
  - Bucket with saved ≥ target = `done`
  - Bucket past deadline and incomplete = `overdue` (also gets focus)
  - Next incomplete after focus bucket(s) = `next`

### Notes
- All functions must be pure (no side effects, no Supabase calls).
- Reuse `toBangkokDate`, `bangkokToday`, `daysBetween` from existing `src/lib/savingPlan.ts`.
- Export shared date helpers if they aren't already exported.

### Acceptance criteria
- [ ] All new types compile without errors
- [ ] Pace calculation handles: no deposits, 1 deposit, many deposits, past deadline, overfunded
- [ ] Daily summary correctly differentiates daily/weekly/monthly/flexible
- [ ] Focus logic: max 2 focus, overdue gets focus, done excluded
- [ ] `npm run build` passes

## Slice 1.7: Period-Aware Streak Logic

**Status**: [ ] pending

### What
Implement the new streak system that respects different saving rule periods (daily/weekly/monthly/flexible) instead of requiring daily deposits for all users.

### Files to touch
- `src/lib/streakCalculation.ts` (new or modify existing)
- `src/hooks/useStreak.ts` (modify if exists, or create)

### Implementation detail

**Streak rules per rule type**:
| Rule Type | Period | Streak +1 | Streak Break |
|-----------|--------|-----------|-------------|
| `fixed_daily` | Day | Deposited ≥ amount today | No deposit today |
| `fixed_weekly` | Week (Mon-Sun) | Deposited ≥ amount this week | Week ends without meeting target |
| `fixed_monthly` | Calendar month | Deposited ≥ amount this month | Month ends without meeting target |
| `increasing_daily` | Day | Deposited ≥ today's amount | No deposit today |
| `increasing_daily_capped` | Day | Same as increasing_daily | Same |
| `flexible` | — | Not tracked | Not tracked |

**Multi-bucket streak**:
- Streak = consecutive periods where ALL focus bucket obligations are met.
- If focus buckets have mixed periods (1 daily + 1 monthly): the streak granularity = finest period among focus buckets (daily in this case).
- Streak freeze still applies: uses 1 freeze per missed day (daily) or missed period.

**Edge cases**:
- User with only flexible focus buckets → no streak displayed.
- User with only monthly focus bucket → streak counted in months ("3 months").
- Bucket transitions from focus → done mid-period → streak not broken for that period.

### Notes
- Reuse existing streak freeze budget/usage tables.
- Bangkok timezone for all period boundaries.

### Acceptance criteria
- [ ] Daily rule: streak breaks on missed day
- [ ] Monthly rule: streak breaks on missed month, not missed day
- [ ] Flexible: excluded from streak
- [ ] Mixed periods: uses finest granularity
- [ ] Streak freeze integration works

**Wizard flow**:

- `localStorage` key: `migration_v0.10.0_{userId}`

- Dashboard shows subtle banner: "Finish setting up your saving goals" with CTA.

### Notes
