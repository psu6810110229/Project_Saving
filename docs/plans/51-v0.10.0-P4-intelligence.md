## Slice 4.2: Smart Permission Prompt

**Status**: [ ] pending

### What
Build a contextual pre-prompt modal that appears when the user first creates or receives a bucket with a deadline. Maximizes permission grant rate by explaining value before triggering the browser prompt.

### Files to touch
- `src/components/PushPermissionPrompt/PushPermissionPrompt.tsx` (new)
- `src/hooks/usePushSubscription.ts` (modify: integrate smart prompt)

### Implementation detail

**Trigger conditions** (show prompt when ALL are true):
- User has at least 1 bucket with a deadline.
- Browser notification permission = `'default'` (never asked).
- User hasn't dismissed the prompt in the last 7 days.

**Prompt UI**:
```
┌─────────────────────────────────────┐
│                                      │
│  🔔 Stay on track                   │
│                                      │
│  Get notified when:                  │
│  • Your bucket deadline is close     │
│  • You're falling behind             │
│  • A teammate hits their goal        │
│  • Someone overtakes you             │
│                                      │
│  [Enable notifications (recommended)]│
│  [Not now]                           │
│                                      │
└─────────────────────────────────────┘
```

**Flow**:
1. User taps "Enable" → call `Notification.requestPermission()`.
2. If granted → call `subscribe()` → auto-enable ALL push preference categories.
3. If denied → store dismissal, don't ask again.
4. "Not now" → store `prompt_dismissed_until = now + 7 days`.

**Where to show**: as a modal overlay, triggered from dashboard or at the end of migration wizard / join wizard.

### Notes
- Only ONE browser permission prompt ever — if wasted on deny, can't re-ask.
- The pre-prompt modal is our chance to explain value before the browser asks.
- Permission state persisted on `notification_preferences.prompt_dismissed_until`.

### Acceptance criteria
- [ ] Prompt shows at correct trigger conditions
- [ ] "Enable" triggers browser permission
- [ ] Grant → auto-subscribe all categories
- [ ] Deny → never prompt again
- [ ] "Not now" → 7-day cooldown
- [ ] Build passes

## Slice 4.3: Bucket Alert Notifications

**Status**: [ ] pending

### What
Implement push notifications for bucket pace changes and deadline approaching events.

### Files to touch
- `supabase/functions/bucket-alerts/index.ts` (new: edge function)
- `src/lib/notifyEvents.ts` (modify: add trigger wrappers)

### Implementation detail

**Pace change detection**:
- On each deposit → recalculate pace for affected bucket.
- If status changed from previous → call `notify_bucket_pace_changed`.
- Store previous status in a lightweight way (could be computed from last notification event, or a `last_pace_status` column).
- Rate limit: max 1 pace notification per bucket per day.

**Deadline approaching**:
- Cron function runs daily (or triggered by `scheduled-saving-reminders`).
- For each bucket with deadline in 7/3/1 days → send notification.
- Deduplicate: one notification per bucket per threshold (7d, 3d, 1d).

**Push payload format**:
```json
{
  "notification_id": "uuid",
  "event_key": "bucket_deadline_approaching",
  "title": "Flight deadline in 3 days",
  "body": "You've saved ฿12,800 of ฿15,000. Save ฿733/day to make it!",
  "url": "/dashboard",
  "tag": "bucket-deadline-{bucket_id}"
}
```

### Notes
- Reuse existing push delivery pattern from `send-nudge` (VAPID, web-push).
- Respect `bucket_alerts_enabled` preference.
- Edge function must be idempotent (safe to re-run).

### Acceptance criteria
- [ ] Pace change triggers push when status worsens
- [ ] Deadline approaching at 7/3/1 days
- [ ] Rate limited (1/bucket/day for pace)
- [ ] Deduplication works
- [ ] Preferences respected
- [ ] Build passes

## Slice 4.5: Monthly Reminder & Weekly Digest

**Status**: [ ] pending

### What
Implement user-set monthly reminders (for monthly saving rules) and a weekly top saver highlight.

### Files to touch
- `supabase/functions/scheduled-saving-reminders/index.ts` (modify: add monthly bucket reminders)
- `supabase/functions/weekly-digest/index.ts` (new: cron, runs Mondays)

### Implementation detail

**Monthly reminder**:
- For each user with a monthly-rule focus bucket where `reminder_day` matches today's date:
  - Check if they've already met this month's target.
  - If not → push: "Hotel reminder: save ฿6,000 this month (currently ฿2,400)"
- Integrated into existing `scheduled-saving-reminders` cron function.

**Weekly top saver** (Mondays):
- For each active room: find user with highest deposit total in the past 7 days.
- Push to winner: "You saved the most in Japan 2027 this week! ฿3,500 total"
- In-app notification to all room members: "Mint saved the most this week (฿3,500)"
- Gated by `achievements_enabled`.

### Notes
- Bangkok timezone for reminder_day check.
- Weekly digest is a separate cron function (Mondays at 9:00 AM Bangkok).
- Handle edge cases: room with 1 member (no "top saver"), tie (both get notification).

### Acceptance criteria

- [ ] Skips if monthly target already met
- [ ] Weekly top saver computed and sent Mondays

## Slice 4.6: Deadline Extension Detection & Notification Settings UI

**Status**: [ ] pending

### What
Detect when users repeatedly extend deadlines and suggest target adjustment. Update the notification settings page with new toggle categories.

### Files to touch
- `src/components/BucketSheet/BucketSheet.tsx` (modify: extension detection)
- `src/pages/NotificationSettings.tsx` (modify: add new toggles)

### Implementation detail

**Extension detection**:
- When user edits bucket deadline → check `bucket_deadline_revisions` count.
- If 3+ extensions for same bucket → show prompt:
  "You've extended this deadline 3 times. Would you like to adjust your target amount or saving rule instead?"
  - [Adjust target] → open target edit
  - [Keep deadline] → dismiss
- Threshold of 3 is based on behavioral psychology: the "three strikes" pattern signals genuine difficulty rather than one-off changes.

**Notification settings updates**:
- Add new toggle sections:
  - "Goal alerts" (bucket_alerts_enabled): deadline approaching, pace changes, overdue
  - "Achievements" (achievements_enabled): bucket completed, weekly top saver, room goal reached
  - "Team updates" (team_updates_enabled): member join/left, overtaking, ownership transfer
- Group existing + new toggles under clear section headers.

### Acceptance criteria
- [ ] Extension detection triggers at 3+ revisions
- [ ] Prompt offers target adjustment
- [ ] New toggle sections displayed in settings
- [ ] Toggles save to DB correctly
- [ ] Build passes
