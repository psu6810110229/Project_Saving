# Phase 2: Smart Room Setup

## Context

Phase 2 builds the creator and member onboarding flows. Creators use a 5-step wizard to set up a room with an expense timeline, shared bucket templates, and smart deadline suggestions. Members join and accept/adjust templates in 3 steps. This phase also adds room ownership transfer, leave/rejoin data preservation, and custom room cover images.

**Prerequisites**: Phase 1 complete (bucket deadline + rule fields exist in schema).

## Slice 2.8: Room Ownership Transfer & Leave/Rejoin

**Status**: [ ] pending

### What
Implement room ownership transfer RPC and improve the leave/rejoin flow to preserve and restore data.

### Files to touch
- `supabase/migrations/0074_transfer_ownership.sql` (new)
- `src/hooks/useRooms.ts` (modify: transfer + improved leave)
- `src/pages/ManageProject.tsx` (modify: transfer UI)

### Implementation detail

**Transfer ownership**:
- New RPC `transfer_room_ownership(p_room_id, p_new_owner_id)`:
  - Validates caller is current `created_by`.
  - Validates new owner is room member.
  - Updates `rooms.created_by`.
  - Creates notification for all room members.
- UI in ManageProject: "Transfer ownership" option, member picker, confirmation modal.

**Leave/rejoin**:
- On leave: delete `room_members` row only (existing behavior). Show confirmation with "your data will be preserved."
- On rejoin (via invite code): `join_room_by_code` detects existing `savings_logs`/`buckets`/`goals` for this user+room → returns `status: 'rejoined'` instead of `'joined'`.
- Client shows "Welcome back!" with restored stats.

**Archive room safeguard**:
- Before archive, show: member count, total saved, and suggest "Transfer ownership?" as alternative.

### Acceptance criteria
- [ ] Transfer RPC validates permissions
- [ ] `created_by` updates correctly
- [ ] All permission checks use new owner after transfer
- [ ] Notification sent on transfer
- [ ] Rejoin detects existing data
- [ ] Archive shows transfer suggestion
- [ ] Build passes
